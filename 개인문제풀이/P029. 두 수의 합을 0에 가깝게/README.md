# P029 — 두 수의 합을 0에 가깝게

- 출처 구분: 공개 연습 기반 변형 문제(함수형). 채용 기출 아님.
- 참고: BOJ2470 두 용액 https://www.acmicpc.net/problem/2470
- 확인일: 2026-10-22. 공식 페이지 본문 접근 실패. 공개 소개 https://jengdeuk.tistory.com/213 와 https://etst.tistory.com/190 의 문제 요약·제한을 참고했다. 공식 원문 재현으로 주장하지 않으며 아래 조건을 학습용 명세로 사용한다.
- 난이도: 투 포인터 기초 응용 / 유형: 정렬·양끝 포인터·최솟값 갱신
- 권장 시간: 35분 / 상태: 학습 통과96점 · 풀이15분

## 문제

순서가 정해지지 않은 서로 다른 정수 배열 numbers에서 서로 다른 두 원소를 선택한다. 두 수의 합의 절댓값이 최소가 되는 쌍을 찾아 값이 작은 순서로 반환한다. 최적 쌍이 여럿이면 아무 쌍이나 허용한다. 0을 만드는 쌍이 존재한다는 보장은 없다. 양수만 또는 음수만 들어올 수 있다.

`public int[] solution(int[] numbers)`

## 제한

- 2 ≤ numbers.length ≤ 100,000
- -1,000,000,000 ≤ numbers[i] ≤ 1,000,000,000
- 원소는 서로 다르며 0은 포함하지 않음
- 반환은 원소값 두 개, 인덱스가 아님. 같은 원소를 두 번 사용 불가.
- 투 포인터로 구현할 것

## 학습용 예시

| numbers | 반환 가능한 답 | 설명 |
| --- | --- | --- |
| [-2,4,-99,-1,98] | [-99,98] | 합-1,절댓값1이최소 |
| [8,3,5,12] | [3,5] | 합8이최소 |
| [-7,2,7,11] | [-7,7] | 합0 |

## 제출

코드,풀이설명,시간·공간복잡도와근거,실제풀이시간. 직접테스트제출요구없음. 정답·포인터이동규칙요청전미공개.

## 제출 평가 — 2026-10-22

- 96/100: 정확성40/40, 효율성20/20, 코드품질14/15, 테스트·경계15/15, 설명7/10. 학습 통과, 풀이15분.
- Java21 실제7,089입력,동일·새 객체 모두 통과. 극값 포함12개 값의 크기2이상 부분집합4,083개,무작위3,000개,학습예시3,최대길이10만3개. 작은 입력은 long 완전탐색 최적값과 비교하고,최적해 동률은 아무 쌍 허용. 큰입력은 명시적 기대 최솟값,원소소속·서로다른값·오름차순 반환 확인. 외부채점기 실행 없음. 검증소스 제외.
- 합의부호에따른포인터이동·절댓값최솟값기록·0즉시반환·left<right 정확. 입력배열은 정렬로 변경됨.
- 원소±10억이므로 합±20억,int범위안전. abs가 int최솟값에서넘치는일도없고,Integer.MAX_VALUE초기값보다첫후보가항상작아startIdx/endIdx가서로다른인덱스로갱신된다.
- 시간O(N log N),투포인터만추가공간O(1). OpenJDK21 Arrays.sort(int[]) 내부 DualPivotQuicksort.tryMergeRuns는 일부 입력에서 new int[size] 병합버퍼를사용하므로 정렬포함최악추가공간O(N). 근거 https://github.com/openjdk/jdk21u/blob/master/src/java.base/share/classes/java/util/DualPivotQuicksort.java . 변수만세어전체O(1)로확정하지말것.
- sum>0이면현재right를유지한채left를증가시켜도합은더커져개선불가,따라서right제거. sum<0이면현재left를유지한채right를감소시켜도더작아져개선불가,따라서left제거. 후보를먼저기록한후제거한다.
- 설명주석의people을numbers로수정하고value는bestAbsSum등으로의미명확화가능. 현재 제출 알고리즘을 그대로 저장했다.
