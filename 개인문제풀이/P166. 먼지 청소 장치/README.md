# P166. 먼지 청소 장치

- 유형: 시뮬레이션
- 출처: 독립 창작 · SSAFY 대비 일반 연습
- 난이도: SWEA D3 수준 비공식 추정
- 권장 시간: 30분
- 상태: 통과
- 참고: 15기 공개 후기 https://hehesu.tistory.com/91 (2025년, 확인일 2026-11-21). 실제 기출 문제가 아니다.

H×W 격자에서 -1은 벽이고 나머지는 먼지량이다. 고정 청소 장치는 (R,C)에 있으며 벽이 아니다. 매일 먼저 모든 칸의 먼지가 동시에 확산되고, 이어 장치가 자기 칸의 먼지를 전부 수거한다. 확산 시 각 칸은 그날 확산 전 먼지량을 5로 나눈 몫만큼을 상하좌우의 각 유효한 칸에 보낸다. 범위 밖과 벽에는 보내지 않는다. 보낸 총량만큼 원래 칸에서 감소한다. 같은 날 받은 먼지는 다시 확산하지 않는다. 청소 장치 칸도 확산에 참여하며 이동하지 않는다. 시작 전 청소는 없다.

입력: T, 각 케이스 H W D R C, 이어 H행 W개 정수. 좌표는 1부터 시작한다. T 1~10, H,W 1~30, D 1~100, 벽 이외 초기 먼지 0~1000000.
출력: #tc 누적수거량 남은먼지총량 최종최대먼지량. 최대량은 벽 이외 칸에서 구한다.

예시 입력:
```text
1
2 3 2 1 2
10 0 -1
0 0 0
```
예시 출력:
```text
#1 3 7 4
```
첫날 확산 후 [6,2,-1]/[2,0,0], 청소 후 [6,0,-1]/[2,0,0]. 둘째 날 확산 후 [4,1,-1]/[3,0,0], 청소 후 [4,0,-1]/[3,0,0].

## 평가

- 24분(01:10~01:34). Java 21 로컬 테스트 100개 모두 통과. 공개 채점기 미사용.
- 단일 칸, 전부 0, 벽에 둘러싸인 칸, 나머지 먼지, 최대 격자·날짜·초기량 및 무작위 입력을 별도 다음 상태 배열을 만드는 기준 구현과 비교했다.
- 정확성 40/40, 효율성 20/20, 코드 품질 14/15, 경계 조건 15/15, 설명 9/10: 98점.
- 시간 O(DHW), 공간 O(HW). 받은 먼지를 next에 보관하고 모든 확산 후 합쳐 동시 확산을 보장했다. next는 전체 다음 상태가 아닌 유입량 배열이다.
- 이름 next를 incoming으로, 주석 long rooms[]를 long[][] map으로 정리하면 의미가 더 분명하다.
