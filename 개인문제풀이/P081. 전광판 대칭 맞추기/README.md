# P081. 전광판 대칭 맞추기

- 학습 난이도 D2 수준 추정. 유형은 2차원 배열과 대칭. 권장 25분.
- 공개 연습 문제의 조건과 입출력을 변형했다. [LeetCode 3240](https://leetcode.com/problems/minimum-number-of-flips-to-make-binary-grid-palindromic-ii/)을 2026-11-09에 확인했다. 원문 출제 연도는 미확인이다. 이 버전은 1의 개수에 대한 배수 조건을 제외하고 SWEA 형식과 새 예시를 적용했다.

H행 W열 전광판의 각 칸은 0 또는 1이다. 한 번에 한 칸의 값을 뒤집을 수 있다. 좌우 대칭과 상하 대칭을 동시에 만족시키기 위해 뒤집어야 할 최소 칸 수를 구한다.

좌우 대칭이면 각 행을 왼쪽에서 읽은 값과 오른쪽에서 읽은 값이 같다. 상하 대칭이면 각 열을 위에서 읽은 값과 아래에서 읽은 값이 같다.

첫 줄에 T가 주어진다. 각 테스트 케이스의 첫 줄은 H W이고 이후 H줄에는 길이 W의 0과 1 문자열이 주어진다. 각 문자열에는 공백이 없다. 1 ≤ T ≤ 10, 1 ≤ H, W ≤ 200. 각 케이스마다 `#번호 최소변경횟수`를 출력한다.

입력 예시

```text
3
3 3
101
010
100
2 4
1001
0110
1 5
11001
```

출력 예시

```text
#1 1
#2 4
#3 1
```

첫째는 오른쪽 아래 칸을 1로 바꾼다. 둘째는 각 열의 두 값이 달라 열마다 적어도 한 번 바꿔야 하고, 켜진 네 칸을 끄면 조건을 만족한다. 셋째는 왼쪽에서 두 번째 칸을 끄면 10001이 된다.

Java `Solution` 클래스의 `main`으로 작성한다. 코드와 함께 풀이 설명, 시간·공간 복잡도, 실제 풀이 시간을 확인한다.


## 2026-11-09 — P081 힌트 후 통과

- 96점. 정확성 40, 효율성 20, 코드 품질 13, 테스트·경계 조건 15, 설명 8. 실제 풀이 시간 미보고.
- Java 21에서 제출 코드와 개선안을 각각 9,425개 입력으로 실행했다. 가로·세로가 1~4이고 면적이 12 이하인 모든 전광판 9,418개는 대칭 결과 전수 열거와 비교했다. 예시 3개와 최대 크기 및 한 줄 경계 4개도 일치했다. 공개 채점기는 미실행했다.
- 대칭 좌표를 서로 겹치지 않는 묶음으로 나눈다. 묶음의 1과 0 중 적은 개수를 바꾸면 최솟값이다. 가운데 행·열에서 같은 칸을 제외하는 분기가 정확하다. 주석의 반복 범위와 4칸 고정 계산을 실제 코드의 범위와 묶음 크기에 맞춘다.
- 시간 O(HW), 입력 배열 포함 공간 O(HW), 계산 보조 공간 O(1). 개선안은 4칸 묶음과 가운데 행·열의 2칸 묶음을 각각 처리한다.
