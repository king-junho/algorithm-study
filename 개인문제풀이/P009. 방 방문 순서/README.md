# P009 — 방 방문 순서

- 출처 구분: 창작 문제(기출 아님), P008 후속 연습
- 참고: https://school.programmers.co.kr/learn/courses/30/lessons/43162 (방·연결 개념 참고, 원문과 입출력·목표 다름)
- 확인·창작일: 2026-10-19 / 난이도: BFS 첫 연습 / 유형: 큐·방문 순서
- 권장 시간: 20분 / 상태: 로컬 검증 통과 · 97/100 · 약 10분

## 설명

rooms[i]는 i번 방과 직접 연결된 방의 목록이다. start에서 BFS로 방을 탐색할 때 큐에서 꺼내는 순서대로 방 번호를 배열에 담아 반환한다. 각 방은 한 번만 방문하고 갈 수 없는 방은 제외한다. 각 목록은 번호 오름차순으로 주어지며 그 순서로 확인한다. 시작 방도 결과에 포함한다.

## 함수와 제한

`public int[] solution(int[][] rooms, int start)`

- 방 수 1~10, 번호 0..rooms.length-1
- start는 유효한 방 번호
- 문은 양방향이고 양쪽 목록에 모두 주어짐
- 자기 연결·목록 내 중복 없음, 각 목록 오름차순, 빈 목록 가능
- Queue와 반복문으로 BFS 구현, 재귀 미사용

## 예시

- rooms=[[1,2],[0,3],[0],[1]], start=0 → [0,1,2,3]. 0 다음 이웃1,2를 순서대로 방문한 뒤 1의 이웃3 방문.
- rooms=[[1],[0],[]], start=2 → [2]. 시작 방만 도달 가능.
- rooms=[[1,2],[0,3],[0,3],[1,2]], start=0 → [0,1,2,3]. 방3은 두 경로로 연결되지만 한 번만 방문.

## 제출

Java 코드, 풀이 설명, 시간·공간 복잡도와 근거, 실제 풀이 시간.

## 최종 평가

- 정확성40/40, 효율성20/20, 코드품질12/15, 테스트·경계조건15/15, 설명10/10 = 97/100, 약10분.
- 사용자 최신 요청으로 직접 테스트 제출 요구 폐지. 이번부터 테스트15점은 에이전트 검증으로 확인한 코드의 경계 처리에 부여하며 사용자의 테스트 역량 점수로 해석하지 않음. 과거 점수는 유지.
- Java 21 실제 검증: 제출 및 개선 코드 각각 6,406개 통과. 방1~5의 모든 무방향 단순그래프·모든 시작점5,405개, 고정시드 무작위1,000개, 방10 완전연결1개. 독립적인 층별 탐색으로 순서 비교. 입력 불변 확인. 외부 채점기 없음. 검증 코드는 커밋 제외.
- [P009.java](P009.java): 제출 로직을 보존하고 import·클래스·공백만 보완.
- 정확성: 중복 없는 발견 순서와 FIFO 큐 처리 순서는 일치하므로 큐에 넣을 때 결과를 기록해도 정답. 주어진 연결 목록은 오름차순이라 별도 정렬 불필요.
- 시간 O(V+E), 추가 공간 O(V). 입력 제외, 출력 포함. 최악의 경우 모든 방과 연결을 확인해야 하므로 이 차수는 적합함.
- 품질 개선: start 특별 처리 대신 start부터 큐에 넣고 공통 반복문 적용. 현재 방 이름 next 대신 current. LinkedList→ArrayDeque 또는 int[] 큐로 객체 비용 감소. int[]를 큐 겸 방문 순서 저장소로 사용하면 박싱·리스트·스트림 변환 생략 가능.
- 개선 배열 코드도 검증했지만 최단 시간이라는 성능 측정은 하지 않음. 개선 코드로 사용자 제출 파일을 교체하지 않음.
