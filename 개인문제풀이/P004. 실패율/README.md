## 문제 요약

1부터 N까지 순서대로 진행하는 게임에서 stages는 각 사용자가 현재 도전 중인 번호다. N+1은 모든 스테이지를 완료했다는 뜻이다.
각 스테이지의 실패율은 그곳에서 멈춘 사용자 수를 그곳에 도달한 사용자 수로 나눈 값이다. 도달한 사용자가 없으면 실패율은 0이다.
1..N을 실패율이 높은 순으로 반환하며, 같으면 작은 번호가 먼저다.

## 함수와 제한

`public int[] solution(int N, int[] stages)`

- 1 ≤ N ≤ 500
- 1 ≤ stages.length ≤ 200,000
- 1 ≤ stages의 각 값 ≤ N+1
- 반환 배열 길이는 N이며 N+1은 반환 대상이 아님

## 예시

- N=5, stages=[2,1,2,6,2,4,3,3] → [3,4,2,1,5]
  실패율은 번호순 1/8, 3/7, 2/4, 1/2, 0/1. 3과 4는 같아 번호순으로 배치한다.
- N=4, stages=[4,4,4,4,4] → [4,1,2,3]
  4번 실패율은 1, 나머지는 0이다.

## 제출

Java 코드, 풀이 설명, 입력 크기를 정의한 시간·공간 복잡도와 근거, 직접 만든 테스트 2개 이상(예상값·실행 여부), 실제 풀이 시간.

## 검토 결과

- Java 21에서 2,008개 테스트 실제 실행 통과(예시 2개, 경계·동률 등 5개, 무작위 2,000개, 최대 크기 1개). 무작위 기대값은 정수 교차 곱으로 실패율 비교. 입력 불변 확인. 외부 채점기 미실행.
- 정확성 40/40, 효율성 18/20, 코드 품질 12/15, 테스트·경계 조건 5/15, 설명·면접 대응 7/10 = 82/100.
- 시간: M=stages.length일 때 O(M log(N+1) + N log(N+1)). 공간 O(N). TreeMap에는 최대 N+1종류의 키만 존재.
- comparator는 내림차순임. 오름차순 range와 ordered stream 안정 정렬 덕분에 동률도 작은 번호 우선.
- remainPeopleCnt가 double이어서 나눗셈은 이미 실수 연산, 바깥 캐스팅 불필요. 인원은 int로 관리하고 나눗셈 전에 캐스팅하면 의도가 명확함.
- 자료구조 개선: 키가 1..N+1인 고정 범위이므로 int[N+2] 집계 시 O(M + N log(N+1)), 공간 O(N).
- 사용자 경계 조건 설명은 타당하지만 구체적인 테스트 입력·예상값·실행 여부 없음. 최종 스테이지 완주자 부재 자체가 아니라 현재 스테이지 도달 인원이 0일 때 나눗셈을 피해야 함.
