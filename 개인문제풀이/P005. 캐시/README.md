# P005 — 캐시

- 출처 구분: 공개 기출 / 카카오 신입 공채 1차 (2017년 실시)

- 공식 확인: 문제 페이지의 해설 링크 https://tech.kakao.com/posts/344 (해설 포함)
- 확인일: 2026-10-16 / 학습 난이도: 실전 기초 / 유형: 문자열·자료구조·시뮬레이션

## 문제 요약

빈 캐시에서 시작해 도시 이름 요청을 순서대로 처리한 총 비용을 구한다. 이름은 대소문자를 구별하지 않는다. 캐시에 있으면 hit로 비용 1, 없으면 miss로 비용 5다. 캐시는 LRU 정책을 따른다. 요청할 때마다 해당 도시가 가장 최근 사용한 항목이 된다. miss 시 공간이 있으면 추가하며, 가득 찼다면 가장 오랫동안 사용하지 않은 도시를 제거하고 추가한다. 캐시 크기 0이면 저장할 수 없다.

## 함수와 제한

`public int solution(int cacheSize, String[] cities)`

- 0 ≤ cacheSize ≤ 30
- cities는 최대 100,000개 도시 이름
- 각 이름은 영문자로만 구성, 최대 20자, 대소문자 구별 없음
- 반환값은 총 실행 비용

## 예시

- 3, ["Jeju","Pangyo","Seoul","Jeju","Pangyo","Seoul","Jeju","Pangyo","Seoul"] → 21. 첫 3회 miss, 나머지 6회 hit.
- 2, ["Jeju","Pangyo","NewYork","newyork"] → 16. 마지막 요청은 대소문자만 다른 동일 도시로 hit.
- 0, ["Jeju","Pangyo","Seoul","NewYork","LA"] → 25. 모두 miss.

## 제출

코드, 풀이 설명, 도시 수·캐시 크기를 구분한 시간·공간 복잡도와 근거, 직접 만든 테스트 2개 이상(예상 결과·실행 여부), 실제 풀이 시간.

## 제출 평가

- 정확성 40/40, 효율성 20/20, 코드 품질 12/15, 테스트·경계 조건 8/15, 풀이 설명·면접 대응 6/10 = 86/100, 학습 통과.
- 제출 로직을 보존해 [P005.java](P005.java)에 저장. import·클래스·공백만 보완. Java 21의 List.removeFirst 사용.
- 실제 검증: Java 21에서 2,012개 통과. 공식 예시 6개, 사용자 예시 1개, LRU hit 갱신·캐시1·캐시0 3개, 고정 시드 무작위 2,000개, 요청 100,000개 최대 입력 2개. 무작위 기대값은 최근 사용 시각을 기록하는 독립 구현과 비교. 입력 불변 확인. 검증 환경 Locale.ROOT, 외부 채점기 미실행. Check.java는 저장소 제외.
- 사용자 테스트: C=3, [Jeju,Pangyo,Seoul,Pangyo,Jeju,Seoul] → 예상 18, 실제 18. 첫 3회 miss와 나머지 3회 hit. 사용자 실행 여부는 미보고. 캐시 교체·대소문자·크기0 사례도 설계 필요.
- 시간: M=도시 요청 수, C=캐시 크기, L=최대 도시 이름 길이. C>0이면 O(M(C+1)L), L≤20을 고정하면 O(MC). C=0은 길이 조회와 곱셈만 하므로 O(1). C≤30까지 고정해 M에 대한 증가만 보면 O(M).
- 공간: 입력 제외 최대 O((C+1)L), 문자열 길이 고정 시 O(C+1), C>0이면 통상 O(C). C=0은 O(1). 전체 누적 할당량과 동시 생존 최대 저장 공간을 구분해야 함.
- 자료구조: ArrayList.indexOf와 앞/중간 삭제 O(C), 마지막 add 상각 O(1). LinkedList는 removeFirst O(1)이지만 indexOf와 인덱스 삭제에 O(C)가 남아 차수 개선 없음. C≤30이므로 ArrayList 선택에 효율성 감점 없음.
- 설명 교정: 앞=오래전 사용, 뒤=최근 사용. hit 시 앞이 아니라 뒤로 이동한다. 처음 들어온 순서만 따르는 FIFO와 구분할 것.
- 품질 보완: cashList→cache, answer→totalCost, index는 반복 내부 선언. Locale.ROOT로 소문자 변환하면 기본 로케일 의존 방지. hit/miss 비용 처리 후 공통 add를 한 번만 할 수 있음.
