# P024 — 공원 산책

- 출처 구분: 일반 공개 연습 문제. 특정 카카오·SSAFY 기출로 분류하지 않음.
- 출처: https://school.programmers.co.kr/learn/courses/30/lessons/172928
- 확인일: 2026-10-21 / 특정 시험 출제 연도: 미확인
- 난이도: 시뮬레이션 기초 응용(학습용) / 유형: 격자 이동·명령 처리·상태 갱신
- 권장 시간: 30분 / 상태: 학습 통과 96/100 · 풀이 시간 미보고

## 문제 요약

직사각형 공원 park의 S에서 출발해 routes의방향·거리명령을순서대로처리한다. O는길,X는장애물,S도통과가능하다. 명령의중간이나도착칸에장애물이있거나공원밖으로나가면명령전체를무시하고그명령직전위치에서다음명령을처리한다. 모든명령후위치를[행,열]로반환한다.

## 함수와 제한

`public int[] solution(String[] park, String[] routes)`

- 공원행수H·열수W각3~50,직사각형
- 문자S/O/X,시작S는정확히1개
- 명령수1~50,각명령형식"방향 거리"
- 방향N북/S남/W서/E동,거리1~9
- 좌측상단[0,0],우측하단[H-1,W-1]
- 첫명령부터순서대로처리,되돌아간시작칸S도이동가능

## 예시

1. park=[SOO,OOO,OOO],routes=[E 2,S 2,W 1] →[2,1]. [0,0]→[0,2]→[2,2]→[2,1].
2. park=[SOO,OXX,OOO],routes=[E 2,S 2,W 1] →[0,1]. 남쪽명령중간장애물로명령전체무시,마지막서쪽명령은[0,2]에서실행.
3. park=[OSO,OOO,OXO,OOO],routes=[E 2,S 3,W 1] →[0,0]. 첫명령범위초과·둘째중간장애물로무시,마지막만실행.

## 제출

Java코드,풀이설명,지도크기·명령수·이동거리를구분한시간공간복잡도와근거,실제풀이시간. 직접테스트제출요구없음. 정답·핵심구현은요청전공개하지않음.

## 제출 평가 — 2026-10-21

- 정확성 40/40, 효율성 20/20, 코드 품질 13/15, 테스트·경계 조건 15/15, 풀이 설명·면접 대응 8/10. 총 96/100, 학습 통과. 풀이 시간 미보고.
- Java 21에서 40,173개 입력을 실제 실행했다. 제출 코드의 동일 객체·새 객체 호출 및 개선 코드를 독립적인 구간 검사 기준 구현과 비교했다. 공식 예시 3개, 3×3 지도 장애물·시작점·방향·거리 전수 및 시작 칸 재통과, 무작위 1,000개, 최대 50×50 지도를 포함한다. 입력 변경 없음. 외부 채점기는 실행하지 않았다. 검증 소스는 저장소에서 제외한다.
- 임시 좌표로 전체 경로를 검사한 뒤 성공한 명령만 현재 좌표에 반영하는 구현이 정확하다. 장애물 뒤의 남은 이동과 범위 초과는 명령 전체 취소, 시작 칸 S는 통과 가능하다.
- H=행 수, W=열 수, Q=명령 수, D=최대 이동 거리. 시작점 검색 O(HW), 명령 처리 O(QD), 총 O(HW+QD). 추가 공간 O(1). O(4)는 O(1)로 정리한다.
- 품질 보완: 시작점은 indexOf 한 번으로 확인하고, isPass는 명령 내부에서 선언한다. 방향 enum에 행·열 변화량을 직접 저장하면 별도 인덱스와 방향 배열의 대응을 관리할 필요가 없다.
- 한 줄 전체 contains("X")는 경로 밖 장애물도 포함하므로 대체할 수 없다. 실제 통과 구간만 검사해야 한다. 한 칸씩 이동하는 현재 방식이 정석적이다.
